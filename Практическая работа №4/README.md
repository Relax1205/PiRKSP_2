# Практическая работа №4. Клиент-серверное взаимодействие с использованием RSocket

Клиент-серверное приложение для передачи данных **АС Поставщиков**
(поставщики, товары, заказы — сущности, аналогичные модулю
«Front-end АС Поставщиков» BootcampLabs) с использованием протокола **RSocket**.

## 1. Используемые технологии (подробно)

### Java 21

Вся логика написана на чистой Java, без фреймворков вроде Spring. Проект
собирается напрямую компилятором `javac` и запускается через `java`, без
Maven/Gradle — все нужные библиотеки лежат готовыми `.jar`-файлами в папке
`lib/` (аналогично тому, как в Практической работе №3 использовались
`reactive-streams` и `rxjava` в виде отдельных jar-ов).

### RSocket

**RSocket** — бинарный сетевой протокол прикладного уровня для
взаимодействия клиент-сервер (и вообще между любыми узлами), построенный
поверх Reactive Streams. Его ключевая особенность — все 4 модели общения
работают по единому мультиплексированному соединению (одному TCP-сокету),
и каждая из них изначально поддерживает back-pressure (получатель может
регулировать, сколько данных ему присылать).

В проекте используются две библиотеки:

- **`rsocket-core`** — реализация самого протокола: интерфейс `RSocket`
  (`requestResponse`, `requestStream`, `fireAndForget`, `requestChannel`),
  классы `Payload` (единица передаваемых данных: `data` + `metadata`),
  `RSocketServer` / `RSocketConnector` для запуска сервера и подключения
  клиента.
- **`rsocket-transport-netty`** — транспорт поверх TCP на базе Netty
  (`TcpServerTransport`, `TcpClientTransport`). RSocket не привязан к
  конкретному транспорту — теоретически то же приложение можно поднять
  поверх WebSocket, просто заменив транспорт.

Каждый `Payload` состоит из двух частей:

- **data** — полезная нагрузка (в проекте — JSON-объект: `Product`,
  `Supplier`, `Order`...);
- **metadata** — служебная информация. В этом проекте в metadata кладётся
  простая UTF-8 строка-маршрут (`route`), например `"product.get"` или
  `"order.track"` — по ней сервер определяет, какую операцию выполнить
  (см. `SupplierRSocket.java`). Это самодельная упрощённая версия
  маршрутизации, которую в проде обычно делает Spring RSocket через
  `@MessageMapping`.

### Четыре модели взаимодействия RSocket

Это центральная концепция протокола — он поддерживает не один, а четыре
принципиально разных способа обмена сообщениями в рамках одного и того же
соединения:

| Модель               | Кто и что шлёт                                                                                                            | Пример в проекте                                                                                                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Request-Response** | Один запрос → один ответ (как обычный REST-запрос)                                               | `product.get` — клиент шлёт id товара, получает один объект `Product`                                                                                           |
| **Request-Stream**   | Один запрос → поток из N ответов                                                                            | `product.stream` — клиент шлёт один запрос, сервер поэлементно отдаёт весь каталог товаров с задержкой                       |
| **Fire-and-Forget**  | Один запрос → без ответа вообще                                                                            | `order.create` — клиент шлёт событие о заказе и не ждёт подтверждения                                                                                   |
| **Channel**          | Поток запросов ⇄ поток ответов (двусторонний, оба независимы по времени) | `order.track` — клиент шлёт id заказов один за другим, сервер параллельно шлёт поток обновлений статуса по каждому |

### Project Reactor

**Project Reactor** — реализация спецификации **Reactive Streams** для
JVM, на которой построен и сам RSocket, и весь реактивный код в проекте.
Основные типы:

- **`Mono<T>`** — асинхронный поток из 0 или 1 элемента (используется для
  Request-Response и Fire-and-Forget);
- **`Flux<T>`** — асинхронный поток из 0..N элементов (используется для
  Request-Stream и Channel).

В клиенте (`ClientMain.java`) демонстрируется именно **реактивная**, а не
блокирующая обработка: `.map()`, `.doOnNext()`, `.doOnComplete()`,
`.onErrorResume()`, `.delayElement()` — элементы обрабатываются по мере
поступления, а не после того, как накопился весь список. На сервере для
Channel используется `.flatMap()`, что позволяет одновременно вести
несколько независимых под-потоков обновлений (по одному на каждый
отслеживаемый заказ).

### Netty

Асинхронный сетевой фреймворк для Java, на котором построен
`rsocket-transport-netty`. Он выполняет фактическую передачу байт по TCP.
В проект добавлен как транзитивная зависимость RSocket, отдельно в коде не
используется.

### Jackson (`jackson-databind`)

Библиотека сериализации Java-объектов в JSON и обратно. Все доменные
объекты (`Product`, `Supplier`, `Order`, `OrderEvent`) передаются между
клиентом и сервером как обычный JSON внутри `data`-части `Payload`.

### SLF4J

Простой фасад логирования, обязательная зависимость `rsocket-transport-netty`
(используется библиотекой RSocket/Netty под капотом для собственных
служебных логов; прикладной код проекта логирует напрямую через
`System.out.println`).

### Reactive Streams

Спецификация (интерфейсы `Publisher`, `Subscriber`, `Subscription`), общая
основа и для RSocket, и для Project Reactor — именно поэтому они
совместимы между собой "из коробки" без адаптеров.

## 3. Обработка ошибок

- `product.get` / `supplier.get` с несуществующим id — сервер бросает
  `io.rsocket.exceptions.ApplicationErrorException` со внятным сообщением
  вместо ответа; клиент перехватывает её через `.onErrorResume(...)` и
  продолжает работу, не падая.
- В канале `order.track` запрос несуществующего заказа не обрывает весь
  канал (в RSocket ошибка обычно закрывает весь Channel) — вместо этого
  сервер отправляет в канал служебное сообщение `{"error": "..."}",
  и обмен по остальным заказам продолжается как ни в чём не бывало.

## 4. Как запустить приложение и снять скриншоты

Понадобится: JDK 17+ установленный и добавленный в `PATH` (`java -version`
должен отработать в обычном `cmd`/PowerShell). Интернет для запуска не
нужен — все библиотеки уже лежат в `lib/`.

### Шаг 1. Открыть два окна терминала рядом (важно для скриншотов!)

Чтобы на одном скриншоте было видно сразу и сервер, и клиента, откройте
**два отдельных окна** (например, `cmd.exe` или PowerShell) и расположите
их рядом на экране (Win+стрелка влево/вправо, чтобы каждое заняло половину
экрана).

В обоих окнах перейдите в папку проекта:

```bat
cd "C:\Users\relax\Documents\PiRKSP_2\Практическая работа №4\rsocket-app"
```

### Шаг 2. Запустить сервер (первое окно)

```bat
run-server.bat
```

При первом запуске скрипт сам скомпилирует исходники (папка `out` создастся
автоматически), затем поднимет RSocket-сервер на `localhost:7000`. Вы
увидите баннер:

```
=========================================================
 RSocket-сервер АС Поставщиков запущен на localhost:7000
 Поддерживаемые маршруты:
   product.get     (Request-Response)
   product.stream  (Request-Stream)
   order.create    (Fire-and-Forget)
   order.track     (Channel)
=========================================================
```

Оставьте это окно открытым — сервер работает, пока окно не закрыто.
**Это окно уже можно скриншотить как доказательство работы сервера.**

### Шаг 3. Запустить клиента (второе окно)

Не закрывая сервер, во втором окне выполните:

```bat
run-client.bat
```

Клиент подключится к серверу и **последовательно** выполнит демонстрацию
всех четырёх моделей взаимодействия, печатая результат в консоль. Полный
прогон занимает около 5–6 секунд (из-за намеренных задержек между
элементами потока — чтобы было видно, что данные приходят постепенно).

### Шаг 4. Что именно скриншотить

Под каждый пункт задания подойдёт свой момент:

1. **Скриншот работы клиента и сервера** — сделайте снимок экрана, где
   видны **оба окна одновременно**: слева — консоль сервера с логами
   обработки запросов (`[Request-Response] Отдан товар: ...`,
   `[Channel] -> обновление статуса: ...` и т.д.), справа — консоль
   клиента с результатами.
2. **Скриншот Request-Response и Request-Stream** — в консоли клиента
   видны блоки `== 1) Request-Response ==` и `== 2) Request-Stream ==`.
3. **Скриншот передачи потока данных** — дождитесь блока
   `== 2) Request-Stream ==` в консоли клиента: там видно, как товары
   выводятся **по одному, с разными метками времени** (`[22:05:42]`,
   `[22:05:43]`, `[22:05:44]`...) — это и есть наглядное доказательство,
   что данные приходят постепенно, а не единым пакетом. Аналогично можно
   показать блок `== 4) Channel ==`, где обновления статусов заказов тоже
   приходят с разными метками времени.
4. **Скриншот Fire-and-Forget и Channel** — блоки `== 3) Fire-and-Forget ==`
   и `== 4) Channel ==` в консоли клиента, а также соответствующие строки
   `[Fire-and-Forget] Получено событие заказа...` и `[Channel] Получен запрос отслеживания заказа...` в консоли сервера.

Итого достаточно 2–4 скриншотов: один общий (сервер + клиент рядом) плюс
1–2 с крупным планом на блоки Request-Stream/Channel, где хорошо видны
метки времени.

### Альтернатива: запуск вручную, без .bat-файлов

```bat
javac -encoding UTF-8 -d out -cp "lib\*" src\suppliers\rsocket\domain\*.java src\suppliers\rsocket\server\*.java src\suppliers\rsocket\client\*.java

REM окно 1
java -Dfile.encoding=UTF-8 -cp "out;lib\*" suppliers.rsocket.server.ServerMain

REM окно 2
java -Dfile.encoding=UTF-8 -cp "out;lib\*" suppliers.rsocket.client.ClientMain
```

Если в консоли вместо русских букв отображаются "кракозябры" — выполните
перед запуском `chcp 65001` (уже встроено в `run-server.bat`/`run-client.bat`).
