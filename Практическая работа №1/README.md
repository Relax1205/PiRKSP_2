# Практическая работа №1. Многопоточность

Java 8+, без внешних зависимостей.

## Структура

```
src/
  task1/  Обработка массива: последовательно, Thread, ForkJoin
    Operation.java       операция (SUM / MAX / MIN): нейтральный элемент + функция объединения
    ArrayProcessor.java  три реализации + RecursiveTask
    Main.java            замер времени и памяти, сравнение результатов
  task2/  Асинхронная обработка запросов с Future
    Main.java
  task3/  Система обработки файлов
    File.java, FileType.java  модель файла (неизменяемая)
    FileQueue.java            потокобезопасная очередь на ReentrantLock + Condition
    FileGenerator.java        генератор файлов
    FileProcessor.java        обработчик файлов одного типа
    Main.java
```

## Запуск

Нужен JDK (javac). Через скрипт:

```
run.bat 1 SUM 10000   # задание 1 (операция SUM/MAX/MIN, размер массива)
run.bat 2             # задание 2
run.bat 3 20          # задание 3 (количество файлов)
```

Или в IntelliJ IDEA: пометить `src` как Sources Root и запустить нужный `Main`.

## Задание 1

Массив из 10 000 случайных чисел, обработка каждого элемента занимает `Thread.sleep(1)`.

- **Последовательно**: один цикл по массиву.
- **Thread**: массив делится на N частей (N = число ядер), каждую часть обрабатывает свой поток.
  Каждый поток пишет только в свою ячейку `results[i]`, а читаются они после `join()`, поэтому
  синхронизация не нужна.
- **ForkJoin**: `RecursiveTask` делит отрезок пополам до порога в 250 элементов:
  `left.fork()`, `right.compute()`, `left.join()`.

Пример результата (16 ядер):

| Способ          | Время, мс | Память, КБ |
|-----------------|----------:|-----------:|
| Последовательно |     45592 |       2498 |
| Thread (16)     |       910 |       1249 |
| ForkJoinPool    |      1082 |      21749 |

Ускорение больше числа ядер, потому что задачи не нагружают процессор, а спят.
В Windows `Thread.sleep(1)` фактически длится несколько миллисекунд, поэтому последовательный
вариант особенно медленный. ForkJoin расходует больше памяти на объекты подзадач и очереди
рабочих потоков. Замер памяти (`totalMemory - freeMemory`) приблизительный.

## Задание 2

Пользователь вводит числа. Каждое число передаётся в `ExecutorService.submit(Callable)`,
а в ответ сразу приходит `Future<Long>`, так что ввод не блокируется. Вычисление квадрата
занимает 1–5 с. Фоновый поток `ResultPrinter` проверяет `future.isDone()` и выводит
готовые результаты. Ошибки (например, переполнение `Math.multiplyExact`) приходят из
`future.get()` как `ExecutionException`. Команда `status` показывает число незавершённых
запросов, `exit` дожидается оставшихся запросов и завершает программу.

## Задание 3

- **Генератор** создаёт файлы случайного типа (XML/JSON/XLS) и размера (10–100)
  с задержкой 100–1000 мс.
- **Очередь** вмещает 5 файлов. `put()` ждёт на условии `notFull`, пока очередь заполнена.
  `take(type)` ждёт на условии `fileAdded`, пока не появится файл нужного типа. Всё
  состояние очереди защищено одним `ReentrantLock`.
- **Обработчики**: по одному потоку на каждый тип, время обработки = размер × 7 мс.
- **Завершение**: после окончания генерации вызывается `queue.close()`. Обработчики
  разбирают оставшиеся файлы своего типа, получают `null` и завершаются.
