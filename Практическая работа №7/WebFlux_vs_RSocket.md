# Отличия WebFlux от RSocket

1. WebFlux работает поверх обычного HTTP: у каждого запроса есть метод, URL и код ответа. RSocket — отдельный бинарный протокол поверх TCP, и все запросы идут через одно соединение.
2. В RSocket четыре модели взаимодействия встроены в сам протокол. В HTTP есть только запрос-ответ, а поток через SSE — это просто ответ на GET, который приходит частями. Fire-and-Forget и Channel через HTTP API напрямую не сделать: ответ на запрос приходит всегда, а SSE работает только в одну сторону, от сервера к клиенту.
3. В RSocket клиент сам говорит серверу, сколько элементов готов принять (backpressure по сети). В SSE сервер просто шлёт события, и клиент на это не влияет.
4. Ошибки в HTTP — это коды статуса (404, 409 и т. д.). В RSocket ошибка приходит отдельным сообщением и закрывает поток.
5. HTTP/SSE можно проверить браузером или curl, а для RSocket нужен специальный клиент.

При этом в обоих случаях в коде используются одни и те же Mono и Flux из Project Reactor. Но они описывают только обработку данных внутри приложения, а как данные передаются по сети, определяет протокол.
